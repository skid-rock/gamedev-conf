# GridFollow — сетка следует за дорожкой

Набор ReaScript для REAPER: сетка проекта подстраивается под BPM аудио на выбранной
дорожке. Нужен для быстрого выделения квадратов, копирования блоков и позиционирования
при сборке микса из треков с разным темпом.

## Как это устроено

Темпо-карта в REAPER одна на проект и живёт во времени — «своей сетки у дорожки» в
программе нет. Поэтому набор эмулирует её: при переключении на другую дорожку вся
темпо-карта переписывается под её айтем — один темпо-маркер с нужным BPM ставится
в точку первой доли.

Отсюда обязательное условие: **все дорожки на таймбейсе Time**. Тогда смена темпа
меняет только разметку, а аудио, огибающие и маркеры стоят на месте.

## Файлы

| Файл | Назначение |
|---|---|
| `gc_gridfollow_lib.lua` | Общая библиотека, отдельным действием не запускается |
| `gc_GridFollow_PrepareProject.lua` | Подготовка проекта: таймбейс Time + шаг сетки в тактах |
| `gc_GridFollow_SetAnchor.lua` | Задать BPM и первую долю для айтема — один раз на трек |
| `gc_GridFollow_ApplyToSelection.lua` | Разово построить сетку под выделенный айтем |
| `gc_GridFollow_Toggle.lua` | Фоновый режим: сетка сама следует за выделением |

## Установка

1. Actions → Show action list → New action → **Load ReaScript...**
2. Выбрать четыре файла, кроме `gc_gridfollow_lib.lua` — библиотека подтягивается сама
   из той же директории.
3. Повесить шорткаты. Библиотеку и скрипты держать в одной папке.

Рекомендуемые сочетания (macOS):

- `⌥G` — GridFollow: Toggle
- `⌥⇧G` — GridFollow: SetAnchor
- `⌥⌘G` — GridFollow: ApplyToSelection

## Порядок работы

1. Один раз на проект — **PrepareProject**. Спросит шаг сетки в тактах: 1 для обычной
   работы, 4 если размечаешь квадратами.
2. На каждый трек — **SetAnchor**: поставить курсор ровно на первую долю, выделить
   айтем, запустить. В диалоге BPM подставляется, если его удалось определить.
3. Включить **Toggle**. Дальше переключение дорожки перестраивает сетку само.

## Откуда берётся BPM

По порядку, первое найденное:

1. Сохранённое значение в расширенных данных айтема (`P_EXT:gc_grid_bpm`)
2. Имя тейка — число в диапазоне 40–300, например `jumpup_intro_174`
3. Имя дорожки
4. Метаданные файла: скрипт запрашивает список идентификаторов и берёт те, где
   встречается `bpm` или `tempo`; значение домножается на playrate айтема

Проще всего прописать BPM в имя файла или дорожки заранее — тогда SetAnchor остаётся
только подтвердить.

Данные хранятся в самом проекте, к файлам на диске не привязаны.

## Что нужно проверить на практике

Скрипты прошли только проверку синтаксиса интерпретатором Lua. Поведение в REAPER
не проверялось — обратить внимание на два места:

- **Прилипание темпо-маркера.** Маркер ставится в произвольную точку времени, но
  REAPER может выровнять его по сетке прежнего темпа. В `applyGrid` стоят флаги
  `1 + 4 + 16` (новый такт, неполный такт слева, сброс сетки линейки) и последующая
  коррекция позиции через `SetTempoTimeSigMarker`. Если фаза всё же уезжает —
  копать в сторону `GetSetTempoTimeSigMarkerBasis`.
- **История отмены.** Фоновый режим меняет темпо-карту без блоков Undo. Если REAPER
  всё-таки начнёт засорять историю, править в `gc_GridFollow_Toggle.lua`.

## Ограничения

- Размер такта фиксирован — 4/4.
- Сетка слева от якоря идёт тем же шагом, но такты нумеруются от якоря.
- Фоновый режим опрашивает выделение раз в 150 мс, значение в `POLL_INTERVAL`.
