# bpm-detect — темп и первая доля трека

Утилита измеряет темп аудиофайла, находит время первой доли такта и проверяет,
держится ли сетка до конца трека. Написана под треки из Suno, где темп на слух
не определяется, а тап по клавише даёт разброс в несколько BPM.

## Зачем понадобилась

В m4a от Suno лежит тег `BPM`, но метрика в нём почти всегда чужая: из 28 треков
альбома у 19 записаны две трети реального темпа (`115.333` вместо `173`), ещё
у четырёх — половина (`88.25` вместо `176.5`). Reaper читает этот тег через
`GetMediaFileMetadata` и подставляет как есть — 115 попадает в разумный диапазон
и выглядит правдоподобно.

Темп, названный в промпте, — тоже не ответ: просили 172, получили от 172 до 180.

Поэтому темп берётся из звука, а тег и промпт работают только подсказками:
сами по себе они врут, но вдвоём задают метрику — «считаем по 173, а не по 86».

## Сборка

Нужен Go и `ffmpeg` в `PATH` (декодирование и сборка клик-трека). Из этого каталога:

```bash
make build
```

В систему (в `GOBIN` или `$(go env GOPATH)/bin`):

```bash
make install
```

## Запуск

```bash
bpm-detect --min 150 --max 200 *.m4a
```

Границы поиска стоит сужать под материал: для jump-up это 150–200, для synthwave
ближе к 90–130. Широкий диапазон впускает кратности, и тогда трек на 174 может
уехать в 87.

Полезные флаги:

| Флаг | Что делает |
|---|---|
| `--hint 174` | опорный темп, если в sidecar его нет или он врёт |
| `--rename` | дописать темп в имя файла, sidecar переименуется следом |
| `--sidecar` | дописать `bpm`, `first_beat`, `bpm_drift` в sidecar-json |
| `--click` | собрать отрывок с щелчками по найденной сетке |
| `--click-from 160 --click-len 40` | какой именно кусок озвучить щелчками |
| `--md файл` / `--json файл` | выгрузить таблицу |
| `--no-drift` | пропустить разбор по окнам, если нужна только цифра |
| `-v` | показать кандидатов, темп по окнам и сдвиг сетки |

## Что в таблице

| Колонка | Смысл |
|---|---|
| **BPM** | измеренный темп, шаг подгонки 0.01 |
| **1-я доля** | секунда, на которой стоит «единица» — то, что просит GridFollow SetAnchor |
| **Дрейф** | разброс темпа по окнам в 30 с |
| **Уход** | на сколько долей разъедется единая сетка от начала к концу |
| **Увер.** | во сколько раз отклик на найденной сетке выше типичного; ниже 1.6 доверять нечему |
| **Такт** | запас «единицы» над соперницей, 0..1; около нуля — сильная доля выбрана наугад |

Решает **уход**, а не дрейф. Локальный темп по окнам скачет от погрешности, а
накопленный сдвиг — это ровно то, что слышно: щелчок в конце трека перестаёт
попадать в удар. Больше половины доли — одной цифрой темпа не обойтись, нужна
темпо-карта или растяжка.

## Проверка на слух

Цифре верить необязательно — попадание проверяется за десять секунд:

```bash
bpm-detect --min 150 --max 200 --click --click-len 40 'трек.m4a'
```

Рядом появится mp3, где поверх музыки щёлкает найденная сетка: «единица» выше
и звонче остальных долей. Если сомнение в том, уезжает ли сетка к финалу, —
озвучить конец: `--click-from 160`.

## Как устроено

1. `ffmpeg` сводит файл в моно 11025 Гц.
2. Звук раскладывается на пять полос однополюсными фильтрами; в каждой считается
   громкость окнами по 23 мс с шагом 5.8 мс. Окно короче нельзя: период кика на
   50 Гц равен 20 мс, и в коротком окне вместо атаки меряется сама волна.
3. Из громкости получается функция новизны: сжатие динамики, положительный
   прирост, вычитание локального фона. Фон нужен, чтобы тихий брейкдаун вообще
   давал вклад, а громкий дроп не перевешивал весь трек.
4. Темп ищется гребёнкой: для пары «темп + фаза» берётся средний отклик функции
   новизны в точках сетки долей. Сначала грубый проход по диапазону, потом
   уточнение шагом 0.01 вокруг лучших кандидатов и вокруг подсказок.
5. Кратность выбирается по опорной метрике: если рядом с заявленным темпом стоит
   вариант почти с тем же счётом, побеждает он. Так `115.33` из тега не выигрывает
   у `173`.
6. Сильная доля ищется по низу: на «единице» бьёт кик, на «тройке» в two-step —
   снэйр, поэтому верх идёт в минус. При спорном счёте решает начало музыки.
7. Уход сетки считается отслеживанием фазы от окна к окну, не дальше четверти доли
   за шаг. Иначе окно перескакивает на оффбит, и ровный трек выглядит уехавшим
   ровно на полдоли.

## Ограничения

- Размер такта считается четырёхдольным.
- Темпо-карту для плывущих треков утилита не строит — только сообщает, что одной
  цифры не хватит.
- Тег `BPM` внутри файла не переписывается: имя файла для GridFollow приоритетнее,
  а перезапись контейнера — отдельная задача (код для неё есть в `suno-download`).
